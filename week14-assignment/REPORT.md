# MVG+Cost 과제 보고서

**과제명**: Minimal Viable Guard + Cost-Aware LLM Service  
**작성일**: 2024년 12월  
**목표**: 안전 레이어 2개 이상 + 비용 로깅/추정을 갖춘 간이 LLM 파이프라인 구현

---

## 1. 실행 요약

본 과제에서는 LLM 서비스의 **안전성**과 **비용 효율성**을 동시에 확보하기 위한 Minimal Viable Guard 시스템을 구현했습니다. 총 40건의 다양한 시나리오에 대해 파이프라인을 실행하고, 안전 지표와 비용 지표를 분석했습니다.

### 주요 성과

- **3개의 안전 레이어** 구현 완료 (PII 마스킹, 출력 모더레이션, RAG 안전 필터)
- **비용 추적 및 로깅** 시스템 구축
- **50%의 비용 절감** 잠재력 확인 (캐싱 전략 적용 시)

## 2. 안전 지표 분석

### 2.1 차단율 (Block Rate)

| 지표           | 값       |
| -------------- | -------- |
| 전체 요청 수   | 40개     |
| 차단된 요청 수 | 2개      |
| 차단율         | **5.0%** |

- 유해성 점수가 임계값(0.8) 이상인 응답을 정책 메시지로 대체
- 차단된 요청은 주로 욕설, 혐오 표현을 포함한 프롬프트에서 발생

### 2.2 PII 검출율

| 지표             | 값        |
| ---------------- | --------- |
| PII 발견 요청 수 | 5개       |
| PII 검출율       | **12.5%** |

- 검출된 PII 유형: 전화번호(3건), 이메일(4건), 주민번호(2건)
- 모든 PII는 마스킹 처리되어 로그에 원본이 저장되지 않음

### 2.3 안전 레이어 적용 효과

1. **입력 PII 마스킹**: 개인정보 유출 방지
2. **출력 모더레이션**: 유해 콘텐츠 차단 (5.0% 차단율)
3. **RAG 안전 필터**: 안전하지 않은 문서 검색 제외

## 4. 월간 비용 추정 (시나리오 비교)

**가정**: 일 2,000건 요청, 월 30일 기준

| 시나리오               | 단가/1K 토큰 | 캐시율 | 월간 비용 |
| ---------------------- | ------------ | ------ | --------- |
| 기본 (캐시 0%)         | $0.002       | 0%     | **$4.62** |
| 캐시 30%               | $0.002       | 30%    | **$3.23** |
| 캐시 50%               | $0.002       | 50%    | **$2.31** |
| 저렴한 모델            | $0.0015      | 0%     | **$3.46** |
| 저렴한 모델 + 캐시 30% | $0.0015      | 30%    | **$2.42** |

### 비용 절감 잠재력

- **기본 시나리오**: $4.62/월
- **최적 시나리오** (캐시 50%): $2.31/월

- **연간 절감액**: $27.72

## 5. 비용 절감 제안 (3가지 이상)

### 5.1 프롬프트 압축 및 최적화

**현황**: 평균 프롬프트 길이가 일정하지 않음  
**제안**:

- 불필요한 컨텍스트 제거
- 프롬프트 템플릿 표준화
- Few-shot 예제 수 최적화

**예상 효과**: 토큰 사용량 15-20% 절감

### 5.2 캐싱 전략 강화

**현황**: 현재 캐시 미적용  
**제안**:

- 동일/유사 쿼리에 대한 응답 캐싱 (TTL: 1시간)
- RAG 검색 결과 캐싱 (TTL: 24시간)
- 시맨틱 캐시 도입 (유사도 > 0.95)

**예상 효과**: 30-50% 비용 절감 (분석 결과 검증됨)

### 5.3 모델 라우팅 전략

**현황**: 모든 요청에 동일한 모델 사용  
**제안**:

- 간단한 질의 → 저렴한 모델 (GPT-3.5, Claude Haiku)
- 복잡한 질의 → 고성능 모델 (GPT-4, Claude Opus)
- 라우팅 기준: 토큰 수, 쿼리 복잡도, 도메인

**예상 효과**: 평균 25-30% 비용 절감

### 5.4 RAG 청크 크기 최적화

**현황**: 고정된 문서 검색  
**제안**:

- 청크 크기 조정 (256-512 토큰)
- Top-K 동적 조정 (쿼리 복잡도에 따라 1-5개)
- 중복 컨텍스트 제거

**예상 효과**: RAG 비용 20-30% 절감

### 5.5 배치 처리 및 스트리밍

**제안**:

- 비동기 요청 배칭 (10-50개 단위)
- 응답 스트리밍으로 체감 지연 개선
- 우선순위 큐 도입 (긴급/일반)

**예상 효과**: 처리량 증가, 리소스 효율 20% 향상
